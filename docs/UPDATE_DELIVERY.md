# 更新公告与旧版兼容

每次正式发布必须同时提供完整安装包、对应的 `.blockmap`、构建生成的完整 `latest.yml` 和 `SHA256SUMS.txt`。只发布安装包会使旧客户端在 GitHub API 访问失败时无法通过备用线路发现更新，2.2.3 起也无法取得应用内下载所需的文件名、大小和 SHA-512。

`docs/update/latest.yml` 是构建生成的完整更新清单的仓库副本，必须包含实际安装包文件名、大小和 SHA-512，并与 Release 附件、EXE 元数据和校验文本一致。将它以 `latest.yml` 名称上传到对应 Release；不要把旧版仅含版本号与发布时间的简化清单用于 2.2.3 及更高版本。

主检测接口成功时，软件显示 Release 正文前四条说明。2.2.3 的 Windows 正式安装版使用同一 `latest.yml` 校验并下载完整安装包；浏览器和源码开发模式仍保留手动下载入口。

## 2.1.0 的入口限制

- 启动约 9 秒后检查一次；失败后没有自动重试。
- 检测成功后显示右上角更新箭头，不会自动弹公告。
- 全屏、沉浸和桌面壁纸模式会隐藏该箭头所在的标题栏。
- 打开更新面板不会重新发起检查。

排查时先从托盘彻底退出并重新打开软件，切回普通窗口，等待约 30 秒后查看右上角更新箭头。网络较慢时可能需要更久。仍未出现入口时，可从本次发布公告提供的新网盘链接获取完整安装包。

上述频率、弹窗和入口限制属于已安装旧客户端的行为，不能通过修改 Release 正文远程改变。
