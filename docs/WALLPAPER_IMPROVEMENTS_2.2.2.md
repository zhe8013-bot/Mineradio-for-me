# 2.2.2 壁纸启动与播放器适配

本次改动缩短恢复上次 Scene 壁纸的等待，并保留原来的开场动画、点击进入流程、账号、歌单、歌词与玻璃设置。

## 实现范围

- 支持的 Scene 项目优先在播放器内通过 WebWallGL 绘制，免去外置引擎启动、窗口校准和捕获链路。
- 不兼容、缺失必需素材或渲染失败时，单次回退到现有 Wallpaper Engine 路径；继续保留失败预览。
- 外置路径并行扫描壁纸库和检测引擎，并行准备引擎与静音副本；校准后的最终静音确认和 DWM 辅助窗口准备也并行。
- 前端复用正在进行的壁纸库加载，避免启动恢复和打开面板重复加载；同一次切换避免重复清理媒体。
- 保留会话取消与资源清理；等待并行任务结束后处理失败清理，防止临时文件或窗口残留。
- 内置场景按现有帧率、屏幕刷新率与 DPR 绘制，保留窗口隐藏/最小化暂停；恢复窗口时继续同一会话。

内置实现是兼容渲染器，并非官方 Wallpaper Engine 原生内核，不能保证所有特效、脚本和项目与官方逐像素一致。官方通用素材仍从本机授权资源读取，不随播放器分发。不支持的尺寸或项目继续使用外置路径。

没有新增运行时 npm 依赖、用户设置、全库持久缓存或安装时壁纸转换。新增的压缩渲染库约 1.1 MiB，另有少量集成代码与许可证；软件仍可能因场景解码而增加瞬时内存和显存。

## 验收方法与结果

以下数据来自一台 Windows 测试机，使用隔离配置，不读取真实登录信息。窗口为 1920×1080、DPR 1，目标为原有 vsync，显示器约 240 Hz。未缩短开场动画。冷启动指受测播放器完全退出后重新启动，不代表重启 Windows 或清空系统文件缓存。

### 五轮启动对比

相同本地 Scene 项目，交替运行当前外置路径与内置路径，各五次。每次使用新配置；桌面 Wallpaper Engine 保持运行。计时从页面导航开始到壁纸层就绪标记，仍包含播放器原有启动流程。

| 路径 | 五次壁纸层就绪时间（秒） | 中位数 |
| --- | --- | --- |
| 当前外置路径 | 16.312 / 15.510 / 15.464 / 15.577 / 15.536 | 15.536 秒 |
| 内置路径 | 5.356 / 5.228 / 5.281 / 5.274 / 5.266 | 5.274 秒 |

本场景中位数减少 10.262 秒，约 66.1%。内置五次均未启动外置渲染会话，退出后资源会话为零。这不是所有壁纸、所有电脑的速度承诺，也不等于点击进入后的用户感知耗时。

另补齐每轮确认 WE 进程已退出的五次有效对照：外置路径为 18.094 / 18.989 / 19.040 / 19.397 / 22.578 秒，中位 19.040 秒；内置路径为 5.272 / 5.366 / 5.403 / 5.672 / 5.987 秒，中位 5.403 秒，样本中约减少 71.6%。内置五次未启动外置会话。测试结束已恢复并校验原桌面布局和壁纸选择。补测期间出现过超时，失败样本保留并排除，补足有效轮次；这些样本存在背景负载差异，不能外推所有机器。启动计时测试专用关闭遮挡节流，产品策略不变。

### 资源占用对照

另一次较早候选版本与本机原安装版 2.2.1 的完整对照，使用同一约 4.52 MiB 场景、相同尺寸和目标帧率、120 秒本地测试音频。有效完整轮次各一次，CPU 另有短轮复核；以下是实测样本，不能当作最终版所有负载的保证。

| 稳定播放指标 | 原安装版 | 内置候选版 |
| --- | ---: | ---: |
| 播放器 CPU | 10.07% | 8.20% |
| 播放器与 WE 合计 CPU（另轮复核） | 9.23% | 8.06% |
| 播放器工作集合计 | 1168.6 MiB | 1207.2 MiB |

| 播放器专用 GPU 内存计数 | 323.5 MiB | 441.4 MiB |
| 播放器与 WE 专用 GPU 内存计数合计 | 762.7 MiB | 778.7 MiB |
| 合计最忙 GPU 引擎 | 18.2% | 18.2% |
| 播放器进程数 | 8 | 7 |
| 播放器句柄均值 | 4899 | 4372 |
| 播放器线程均值 | 263 | 262 |

CPU 按 20 逻辑处理器整机 100% 归一。工作集合计可能重复共享页；私有提交不等于驻留 RAM；跨进程显存计数也可能重复共享资源。桌面 WE 在两组均运行，其负担不能全算到播放器上。父页面 RAF 不是官方 WE 实际输出帧率。部分外置捕获出现 WGC 错误后恢复，未从样本中删去。

结论限于这些样本：启动明显缩短，CPU 与帧间隔没有显示恶化，但播放器本身的内存、显存和启动内存峰值增加；不能宣称所有资源全面减少。

### 功能与故障回归

- 15 个本地 Scene 项目均加载成功，输出画布 1920×1080；没有兼容性警告，也没有借助外置回退冒充内置成功。
- 真实 Electron 测试通过帧率调整、DPR 变化、全屏、最小化恢复、20 次切换、隐藏状态启动和启动取消。
- 缺失必需公共素材时不误报成功，只尝试一次外置回退，并释放资源会话。
- 沙箱验证通过：场景无法读取父页面 DOM、存储、Node 或桌面桥；未授权网络、导航、目录穿越请求被拒绝。
- 并发准备回归覆盖任务重叠、单项失败、取消及清理顺序。
- 现有快速检查通过，包括原有 202 项默认值和开场时序保护。
- 34 项针对性回归通过，包含父页/沙箱帧隐藏和后台定时器挂起后的首帧超时计时、事件监听清理。最终源码的串行生命周期验收与最终打包程序的两次完全退出后恢复均通过；默认使用内置引擎，原进入动画存在。
- 完整 Electron 检查仍有 `dual/dual translation rows invalid` 和 `dual/multi translation rows invalid` 两项原有失败；未修改个人仓库 main 基线可复现同样失败，本次不修改歌词实现。

同一 vendor 与绘制路径另完成 30 分钟持续渲染：180/180 次采样均处于绘制状态且超过 20 FPS，没有兼容性警告，退出后资源会话为零。该长测启动于最后的首帧可见性修复之前，已完成合成后的绘制路径未变；首帧计时由新增回归另行覆盖。前段与最后五分钟私有提交均值约 1067 / 1098 MiB，约增加 31 MiB，不能由此排除更长期的内存增长。

最终源码还完成本地测试音频播放、最小化恢复、再次切换、关闭壁纸与正常退出的资源复核，两组退出均无受测子进程残留。该复核使用双方相同的测试专用防遮挡节流参数，且与部分长测重叠、背景负载不完全一致，不用于宣称最终版资源节省百分比。一次未控制遮挡的补测发生首帧超时并回退，原始失败样本保留；多个测试播放器占用不同端口时也产生过恢复失败，因此安装前完整程序恢复检查采用串行运行。

本机安装版已更新至 2.2.2，程序文件与验收包一致；安装前记录的 8 个顶层用户配置文件在安装后字节不变。安装后的实际可执行程序通过隔离配置两次冷启动，并通过真实用户配置两次正常启动：所选壁纸保持启用并由内置引擎恢复，未播种或改写真实壁纸选择，原进入动画存在。旧安装程序和源码历史回滚副本仅保留本地。

## 隐私、维护与限制

源码、测试、许可证与本说明同步到个人仓库 `Mineradio-for-me` 的 `main`，不创建功能分支。经用户确认，2.2.2 安装包已发布到该仓库的 [正式 Release](https://github.com/zhe8013-bot/Mineradio-for-me/releases/tag/v2.2.2)，并附更新清单与文件校验值。发布内容不包含账号、Cookie、歌单、配置、私人壁纸包、纹理、缓存或原始截图。

第三方来源、固定版本、补丁、许可证和重构建方法见 [THIRD_PARTY_PORTS.md](THIRD_PARTY_PORTS.md)。内置渲染器有安全沙箱与资源预算，但复杂场景仍可能占用较多 GPU/内存。

未测：所有创意工坊项目的视觉等价性、不同显卡/多屏组合、重启 Windows 的文件冷缓存、官方 WE 输出帧率、精确物理磁盘 I/O、功耗和温度，以及联网歌曲提供商与所有歌词复杂负载。引擎进程未运行的补测不等于 Windows 文件冷缓存测试。
